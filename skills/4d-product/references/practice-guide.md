# Product Discovery & Prioritization: practice guide

## Prioritization without false precision

Use an existing prioritization method if the project has one. Identify where its inputs come from and mark estimates as estimates. Do not turn sparse anecdotes into precise reach or ROI scores. A lower-confidence opportunity may merit discovery rather than a build commitment.

## From discovery to delivery

Record the chosen problem, approved scope, excluded work, user journey, acceptance criteria, design references, and unresolved assumptions. Transfer evidence rather than just a feature title. Human approval of a discovery experiment does not automatically authorize implementation. Changes within an already approved scope do not need a fresh ceremonial gate.

## Worked example (fictional)

**Input:** A team has twelve dashboard requests. Nine repeat the same interview; a filter already supports the task but is difficult to find. Data freshness is also uncertain.

**Avoid:** Treating twelve messages as twelve independent customers and ranking a new dashboard first.

**Reasoned response:** Deduplicate sources and inspect the actual task. Propose a short observation of the existing filter and a small discoverability change if supported. Keep data freshness as a competing explanation. Do not call the feature validated from stakeholder enthusiasm.

**Example artifact:** Problem: users need to identify overdue orders. Evidence: one repeated interview plus three other messages, whose independence still needs checking. Options: surface the filter; improve data freshness; build a dashboard. Next test: observe the task with current and revised navigation. Decision remains a proposal, not a roadmap commitment.

**Follow-up:** Observe whether users identify the right orders, how long it takes, and whether they return to the old workaround. Record data freshness and training changes as possible confounders.

These are illustrative outputs, not verified results. This skill uses the [4D Framework](https://4dframework.org/) as a proposed competency model; it is not a certification.
