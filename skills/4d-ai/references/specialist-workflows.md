# Working with specialist workflows

4D carries context across boundaries. Specialists perform the domain task. Neither a skill name nor a handoff expands user authorization.

## With installed skills

Identify the task before selecting a specialist: support investigation, product decision, implementation, verification or customer follow-up. Use available descriptions and read only the relevant instructions. Do not force a product review between support and an already approved bug fix. Do not run two competing workflows for the same purpose.

Honor host and project instructions. If a specialist's suggested process duplicates a completed approval, carry the existing decision forward within applicable instructions. If requirements genuinely conflict, expose the precise conflict and continue unaffected work; do not silently override it. Never claim a tool or skill was used unless it was actually available and used.

Suggested handoff content: desired outcome; source-backed facts and unknowns; exact decision and boundaries; requested action; evidence needed back. The receiver may challenge the evidence or return a specific missing prerequisite.

## Without installed skills

Perform the authorized task using available tools and expertise, or prepare a handoff for the responsible person when the needed capability is missing. Another plugin, tracker or coordinator agent is not a prerequisite. Do not install integrations automatically.

## Illustrative combinations

- A customer-support specialist investigates and drafts; an engineering specialist implements an approved change; support prepares the closure message. 4D retains the outcome and decision record across these steps.
- A sales specialist prepares a proposal; a delivery specialist checks feasibility. 4D keeps proposed dates distinct from authorized commitments and customer acceptance.
- An operations specialist proposes a process change; a finance specialist checks its assumptions. 4D retains uncertainty and the agreed comparison for the pilot.

These are composition patterns, not verified integrations with particular plugin versions. Specialist instructions, available tools and host behavior must be tested together.
